# 性能基线与冒烟清单

本目录只回答一个问题：**这次重构到底有没有变快**。三个指标在动手前测一次、收尾时再测一次，
数字写进 `baseline.json` 与 `docs/performance-report.md`。

## 指标口径

| 指标 | 定义 | 采集方式 |
| --- | --- | --- |
| `open_100k_rows` | 从执行 `select *` 到「10 万行 × 5 列」全部转成表格单元格的总耗时 | 自动：`pnpm bench:rows` |
| `bundle_size` | 前端 `dist/` 产物总字节数 | 自动：`pnpm bench` |
| `cold_start` | 双击 release 可执行文件 → 主窗口可交互 | 手工（需真实窗口） |
| `scroll_fps` | 打开 10 万行结果集后快速拖动滚动条，DevTools Performance 记录的平均帧率 | 手工（需真实窗口） |

冷启动与滚动帧率无法在无头环境复现，因此不做脚本化，只记录人工读数；不做测量就不能声称「更快」。

## 用法

```bash
pnpm bench                 # 记录前端产物体积等静态指标
pnpm bench:rows            # 跑 Rust 侧 10 万行取数 + 单元格转换基线
```

结果写入 `scripts/bench/baseline.json`（当前分支的最新一次读数）。

## 手工冒烟清单

每次阶段性改动后逐项确认（约 5 分钟）：

1. 启动应用 → 托盘图标存在，关闭窗口后进程仍在，双击托盘可唤回。
2. 新建 SQLite 连接（选一个本地 `.db`）→「测试连接」通过 → 保存后出现在左侧树。
3. 展开连接 → Tables / Views / Query 三级结构正常，表旁的数量角标正确。
4. 打开某张表的数据页 → 分页、排序、单元格编辑各操作一次；不改真实数据时直接关闭。
5. 表右键菜单：查看建表语句、显示列、删除表（在临时库上做）。
6. SQL 编辑器执行 `select 1` 与 `select * from <小表> limit 10` → 结果表格与耗时正常。
7. 保存查询 / 重命名 / 删除各一次。
8. 导出向导：勾选一张表 → 生成 SQL/JSON/CSV 任一格式到临时目录。
9. 对不支持的操作确认**有明确报错**，而不是静默无反应（例如对 SQLite 点「更新注释」）。
10. 打开一个非 SQL 数据源（Redis/S3 任一，若本机有环境）确认树与操作未受影响。

## 注意

- 手测前先备份 `~/.easyviewer.db`：本次重构按既定决策**不迁移旧表结构**，遇到旧结构会重建。
